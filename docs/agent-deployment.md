# Agent 本机部署指南

用户将[首页提示词](../README.md)交给 Agent 后，按本文完成识别、测量、生成、加载和验收。配置与分流行为以当前 `tools/build.py`、`catalog/` 和运行内核为准。

## 执行条件与授权

需要能在用户电脑上读取文件、执行终端命令的 Agent，以及可用的 Clash / Mihomo 客户端。只在远程沙盒运行的 Agent 不能替用户读取本机订阅或加载配置，应如实说明执行范围。

首页提示词授权本机读取、备份、生成、持久配置导入、重载和业务验证。执行前遵守用户的实际授权与本机适用指令。购买套餐、创建付费服务、发布私人资料、安装新网络驱动或修改整机 TUN / DNS 范围需另行确认；已授权的本机部署步骤持续完成。

当前公开生成器要求 `primary`、`bulk` 两份来源，`temporary` 可选。相同来源不能伪装成两个独立订阅来宣称冗余。没有可用订阅时可以完成演示与脱敏方案，并说明真实部署所缺条件。

## 1. 读取项目与本机现场

按顺序读取：

1. `README.md`、本文、[分类思维导图](routing-mindmap.md)。
2. [部署与更新](deployment.md)、[测量指南](measurement.md)、[额度保护](quota-and-failover.md)、[规则说明](rules.md)。
3. `catalog/services.json`、`catalog/routes.json`、`examples/settings.example.yaml`、`tools/build.py`、`tools/measure.py`。
4. 仓库与目标配置目录的适用指令，客户端的持久配置来源和运行状态。

已有仓库先检查工作区与版本，保留用户修改。新环境按 README 创建虚拟环境、安装 `requirements.txt`、执行现有测试与演示。演示输出不得导入为真实连接。

发现客户端配置目录后，只在本机解析订阅与控制接口信息，不打印完整 YAML、订阅 URL、节点服务器、出口 IP、密码或控制器凭据。使用成熟 YAML 解析库，错误摘要也需要脱敏。

同时识别当前生效配置、生成配置、增强脚本、服务内核工作目录与实际代理端口，避免把磁盘上的某份旧订阅当成正在运行的配置。

## 2. 一次性补齐非敏感信息

先复用用户已有信息，再从客户端或本机记录读取。只询问仍然缺失、会改变部署选择的信息：

- 使用地点和运营商；本任务只部署当前电脑。
- 常用 AI、开发、社交、下载服务及优先级。
- 各订阅脱敏别名、套餐价、额度、已用量、重置与到期时间。
- 节点倍率、月预算和主要故障表现。

报价、额度或倍率没有可靠来源时标记未知，不根据流量提示名称或机场品牌猜测。人民币和美元分别列出，缺失价格不写成零。

## 3. 备份并建立全部节点清单

将备份保存在 `local/` 的独立子目录，记录当前配置和组选择的恢复位置。备份要覆盖实际持久配置，而非只保存客户端生成的临时文件。

读取全部来源节点，排除额度提示等非节点条目，建立本机清单：

| 字段 | 用途 |
|---|---|
| 来源别名、节点别名 | 标识订阅和节点；公开材料仅使用别名 |
| 倍率及证据 | 计算成本；未知倍率节点暂不进入自动池 |
| 独立入口、重复参数、出口变化 | 识别候选故障关联，原始参数仅保留本机 |
| 逐服务结论、时间、请求方法与状态 | 决定 `services` 与验收日期 |
| 互动与容量资格 | 决定 `roles` |
| 未通过原因、手动用途 | 保留暂不适合自动选择的节点 |

相同连接参数的多个别名可以合并测量并保留映射；共用入口不能算独立备用。每个独立候选先做至少三轮轻量连通检查，失败记录保留。全量清单不意味着对所有节点反复下载大文件。

## 4. 隔离测量并确定候选

使用隔离测试内核和独立本机端口，明确选择叶节点，检查实际出口。隔离配置只能保存在 `local/` 或 `.scratch/`，不能让测试请求悄悄使用生产自动组的其他节点。

1. 对准备进入自动池的候选进行至少三轮轻量与业务检查，记录中位数、失败和出口变化。
2. 使用 `tools/measure.py --kind latency --rounds 3 --proxy <本机测试代理地址>` 测量当前已选出口的复用请求。地址由 Agent 从本机确定；无需用户发到聊天中。
3. 使用 `--kind bandwidth --rounds 3` 仅测试筛选后的低倍率容量候选。每个候选约下载 30 MB，按倍率计费。
4. 使用 Net.Coffee 的 IP / GPT / Claude / DNS / WebRTC 与[连通页面](https://ip.net.coffee/link/)作补充观测，保留测试范围，避免在公开材料暴露出口。
5. AI 按服务分别验证支持地区、匿名接口语义和用户已有登录会话里的真实请求。没有会话访问权限时，保留匿名结果并标记账号验收未完成；不索取或写入令牌。
6. 晚高峰另测一轮并单独统计。当前不在当地晚高峰时记录待验收，只有用户明确要求后续检查时才创建预约或自动化。

遵循[测量指南](measurement.md)对 401、405、403、404 的具体判断。网页可达、HEAD 判活、第三方评分与已登录生成是不同证据。

生成器本身不执行全量扫描，也不会抓取信誉评分；Agent 用本机可用工具执行检查并填写结论。缺少自动操作能力或接口失败时，报告具体未测范围，不填虚假的 `qualified: true`。

## 5. 填写设置并生成

来源角色不绑定机场品牌：`primary` 是 AI 优先来源，`bulk` 是日常和容量来源，`temporary` 保留短期手动用途。按[思维导图](routing-mindmap.md)与本机证据选择。

正式 `local/settings.yaml` 至少满足：

- `demo: false`，两份主力来源路径相对于设置文件，真实导出 YAML 位于 `local/`。
- 节点 `alias` 唯一；映射到真实来源名称，倍率是已确认的正数。
- `qualified: true` 必须有真实 `qualified_on` 日期；`services` 仅列实际通过的服务 ID，禁止 `*`。
- `roles: [interactive]` 表示互动资格，`roles: [bulk]` 表示容量资格，两者可以同时具备。
- 自动池只接受倍率不超过 1 的已验收节点。高倍率节点保留手动用途，不能篡改倍率绕过筛选。
- 同服务尽量保留多个候选、不同入口和备用来源。生成器沿 `nodes` 顺序排列同来源候选，Agent 应根据业务结果安排顺序。
- 无候选组会生成为 `select: [REJECT]`。用户需要的服务不能带着这种配置宣称可用；未使用服务可以明确保留待验收状态。

`base` 可保留现有 DNS、TUN、hosts 等网络字段，但生成器会替换节点、组、来源和规则。Agent 必须核对外部规则引用、`dialer-proxy` 等依赖及接口设置的兼容性。来源禁用证书校验时，不应默默设置 `allow_insecure`；按用户已有决定处理并披露范围。

从仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tools/build.py --settings local/settings.yaml
# mihomo 替换为已发现的实际内核路径。
mihomo -t -d output -f output/config.yaml
```

这些步骤生成和检查文件；客户端导入是下一步。

## 6. 加载到实际客户端

### Clash Verge Rev

按[部署指南](deployment.md)发现客户端持久配置接口和内核 HomeDir，将 `providers/` 放入内核实际允许的工作目录，并将生成配置导入为本地配置。已有增强脚本的环境可更新持久脚本，但需明确本机实现与公开生成器的区别。

优先使用已发现且受支持的本机接口或配置机制。不要写死个人 profile ID、命名管道、控制端口或服务目录。修改持久配置后，通过实际可用的客户端重载机制加载，再读取运行态核验。

### 独立 Mihomo

先核对现有实例与端口占用，再按用户原有启动机制部署 `config.yaml` 和全部引用的 provider 文件，保留一致的工作目录。不要用另开一个内核实例造成两个实例争抢同一端口。

任何客户端出现来源数量为零、文件缺失、路径拒绝或重载失败时，立即修正对应目录与加载机制。权限不足、缺少必要接口等实质阻塞需要明确报告；磁盘生成成功不能代替运行加载。

## 7. 验证运行态与备用

通过已发现的本机控制接口或客户端状态核对：

- 当前加载的配置、全部被引用的 provider 与实际节点数量。
- 每个需要的业务组的候选、选择与顺序，以及精确例外在父域规则之前。
- 业务请求的匹配规则、服务组与最终叶节点。控制凭据只在本机使用，不打印。
- GitHub 网页、Raw、API、源码下载与 `git ls-remote`；AI 网页、匿名接口和可访问的已登录请求分别测试。
- 在隔离测试环境使首选候选不可用，验证新连接切到另一候选或备用来源；复测后恢复原始测试条件。无需破坏正式节点或修改供应商配置。
- `--block-primary` 的额外生成、加载和旧连接处理按[额度保护说明](quota-and-failover.md)核验，明确是手动触发还是已有本机后台机制。

路由不能保证账号资格或服务地区开放；代理通路可用但业务拒绝时，保留业务错误与验证范围，不把它改写为连接成功。

## 8. 交付记录与恢复

将含私人细节的交付保存在 `local/` 或 `reports/`：

1. 本机分类思维导图与请求流转图：服务组 → 来源池 → 节点别名，逐分支说明原因。
2. 服务到出口表、全部节点清单、重复与失败原因、倍率和候选顺序。
3. 人民币 / 美元月成本、已用额度与剩余周期、数据来源；本机测量不能替代供应商账单。
4. 实际加载证据、逐服务测量结果、备用测试、未验收的账号 / 长连接 / 附件 / 晚高峰项目。
5. 订阅更新、重新映射、重建与重载的方法；精确的本机备份恢复步骤。

完成条件：用户要求的服务已有实际运行匹配和相应业务证据，provider 数量正常，必要检查通过且恢复路径可用。缺项按具体范围写明，不使用“全节点纯净”“所有账号可用”等无证据结论。

公开分享时重新制作脱敏材料，执行 `tools/check_public.py` 并审查差异。部署任务默认不包含上传本机交付物到 GitHub。
