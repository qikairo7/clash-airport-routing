# 匿名案例：2026-10-01 上午复测

范围是一台 Windows 电脑、三份机场订阅、Mihomo v1.19.31。节点和订阅用“主订阅、容量订阅、临时订阅”表示，真实 IP、服务器、凭据与原始浏览数据不公开。

这是本机真实复测的汇总，原始私有日志未随仓库发布，因此外部读者不能仅凭此文独立重算所有历史结果。公开工具可在自己的环境重测；模板生成与回归测试另有可运行代码。

## 流量问题先于提速

历史流量表共 1279 条，实际约 33.742 GiB，按倍率约 104.612 GiB。其中一条 3 倍家宽节点约占结算量 88%。表里没有网站和进程字段，不能归因给某个 AI 应用。

改为自动池仅使用 1 倍候选，GitHub 文件、容器和媒体不自动回退主订阅。主订阅按季分摊约 ¥61.67 / 月，容量订阅 ¥114 / 月，总计约 ¥175.67 / 月，新增美元成本 $0。

## 全量节点与规则

- 567 条配置记录包含 5 条额度提示与 13 个重复别名，对应 562 个节点名称、549 组独立连接参数。
- 549 组均执行三次出口观察、10 项轻量业务检查及出口对应的质量查询；539 组三轮采样合格。合格不等于所有节点都适合全部 AI 服务。
- 后续筛选主要 AI 自动池为 20 个主订阅 1 倍候选与 6 个容量备用；Google 系服务为 17 + 6。普通互动为 23 个容量候选与 25 个主订阅低倍率候选。
- 整个私有配置最终 8012 条规则、100 个组。23 个自动 AI 服务按主 / 容量分别拆分，共 46 个独立检查来源。公开模板复用了结构，未复制全部私有规则与参数。

## 最终顺序测量

隔离测试核心退出，其他主动测试结束后，在正式规则下顺序测量。用户既有后台流量与配置自身的健康检查无法全部消除。

| 业务 | 三轮复用请求中位数 | 三轮中位数 | 本轮最大值 |
|---|---|---:|---:|
| ChatGPT | 387 / 420 / 414 ms | 414 ms | 896 ms |
| GitHub | 123 / 200 / 218 ms | 200 ms | 472 ms |
| X | 239 / 224 / 252 ms | 239 ms | 278 ms |

三轮单连接各下载 10 MB，完整长度、状态 200、连接数 1：10.51 / 25.65 / 31.13 Mbps，中位数 **25.65 Mbps**。更早一轮中位数 39.33 Mbps，当前仍有波动，没有性能显著改善的证据。

三次 1 MiB 匿名上传通过，约 1 Mbps，属于普通容量路径。单连接限速下载持续 122.34 秒并完整结束；这是传输测试，不是实际 AI 生成流。

## 网站与业务结果

Net.Coffee 原页面无请求拦截，部署后三轮每轮 48 个目标 × 8 次，合计 1152 次正式探测；三轮均为：国内 12/12、日本 4/4、美国 20/20、全球 10/12，即 **46/48**。

Takealot 的探测地址返回同源限制 / 403，多线路没有通过。Noon 出现 HTTP/2 错误、普通请求超时或 403，仍未通过。未关闭全局协议或安全检查去制造通过结果。

31 项业务最终均取得预期匿名响应。GitHub 网页、Raw、API、源码文件和 Git HTTPS `ls-remote` 均验证；部分 API 的 401/405 只说明网关正常拒绝匿名身份或请求方法。

GitHub API 曾返回匿名额度耗尽的 403。主动检查候选后更换到另一容量出口并恢复 GET 200；本轮没有测出仅靠定时检查对额度耗尽的自动恢复速度。

Net.Coffee 当时给 ChatGPT、Claude 出口评分 100，地区支持正常；普通海外出口被标为机房 / 公开代理 / 风险 75，未提升为严格 AI 出口。DNS 30 个检测项与 WebRTC 页面未报告泄露；评分与泄露结果只代表当时观测。

全球 Ping 页测远程探测服务器到当前出口，不能作为家庭电脑到机场入口的延迟。无登录浏览器没有验收用户账号真实生成、附件或风控。

## 本轮确实修正的故障

原共享检查结构下，同入口 81 个主订阅节点失效时，ChatGPT / Codex 在启动约 203 秒仍尝试不可达首节点。实际 HEAD 与 GET 结果不同，加上共享来源状态，阻碍了备用。

修正为每服务 × 订阅独立文件来源；ChatGPT robots 的 HEAD 仅作网络检查，trace GET 另验。最后隔离故障测试没有主动测速改变候选健康状态：

| 模拟故障 | 观察结果 | 全部通过观察时点 |
|---|---|---:|
| 同入口 81 个主订阅节点失效 | 五个核心网页服务使用不同入口主订阅备用 | 启动后 77.34 秒 |
| 全部 336 个主订阅节点失效 | 五个服务使用容量订阅备用 | 启动后 74.51 秒 |
| 全部容量节点失效 | 开发、X、Telegram 转主订阅 1 倍；三个下载组失败，未转主订阅 | 66.91 秒 |
| OpenAI API 单独验证入口 / 全部主订阅故障 | 分别转另一主订阅候选 / 容量备用，返回匿名预期 401 | 61.19 / 60.31 秒 |

这些是离散观察时点，包含启动和请求耗时，不是精确切换秒数，首次观察仍有失败。额度保护另验证关闭一条旧主订阅连接，锁定目录并保留容量 AI 备用；该保护测试主动检查了备用，不混入上述自动切换耗时。

## 仍未验收与限制

- 晚高峰数据尚未取得。
- Takealot / Noon 的探测目标未通过。
- 七个 AI 服务保留手动入口，没有足够的自动业务判活证据。
- 登录后的 AI 生成、真实附件上传、账号风控和 Telegram 语音未作为本轮匿名测试的通过项。
- 私有运行环境存在供应商原始证书校验限制；没有取得可信链的来源不能标为证书安全通过。
- 保守流量保护不能替代供应商账单，更不能证明多设备流量的精确硬上限。
